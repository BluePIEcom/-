# 架构

## 组成

```
┌──────────────────────────────────────────────────────────────┐
│  DSH 进程                                                     │
│                                                              │
│  会话 A（插件 1）      会话 B（插件 2）      会话 C（插件 3） │
│      │                     │                     │           │
│      └──────────┬──────────┴──────────┬──────────┘           │
│                 │  MCP (stdio)        │                      │
│                 ▼                     ▼                      │
│        ┌──────────────────┐   ┌──────────────────┐           │
│        │ shared-memory    │   │ 插件自己的工具    │           │
│        │ MCP server       │   │ (读写各自业务)    │           │
│        └────────┬─────────┘   └──────────────────┘           │
└─────────────────┼────────────────────────────────────────────┘
                  │ 纯文件 IO
                  ▼
      ┌───────────────────────────────┐
      │ 记忆目录                       │
      │  owner.md    (trusted, 只读)   │
      │  self.md     (self, 可写)      │
      │  inbox.md    (untrusted, 可写) │
      │  adapters/   (*.mjs 摘要适配器) │
      └───────────────────────────────┘
```

一个 MCP server 被 DSH 在**进程级**拉起（profile 级配置），
所有会话共享同一个 server 实例与同一份记忆目录。这正是我们想要的：
**共享是默认的，隔离靠 channel 与工具名。**

## 数据流

### 写

```
agent ──memory_append_inbox(text)──▶ 校验（长度/可写/类型）
                                   ▶ 按 channel 的 trust 决定渲染方式
                                     · untrusted → 逐行 "> " 引用化 + "[untrusted]" 前缀
                                     · self/trusted → 原样正文 + 时间戳小标题
                                   ▶ appendFileSync + 超限按行轮转
```

### 读

```
agent ──memory_read(channel?)──▶ 固定横幅（来源 + 该级别的处理规则）
                              ▶ 正文尾部 N 行（不足则全给，并注明总量）
```

横幅每次都带、不可关闭：这是"结构性提醒"，不依赖人设里写没写。

### 跨插件查询（digest）

```
agent ──digest_list──▶ 扫 adapters/ 下 *.mjs，列出 id/title/trust
agent ──digest_read(id)──▶ 调适配器的 read()
                        ▶ 用该适配器声明的 trust 渲染横幅
                        ▶ 异常只影响这一个适配器
```

拉模式（pull）：没人查就不产生任何开销。

## 关键不变量

1. **信任由文件决定**。`channel.trust` 是配置里写死的，运行期不可改。
2. **`trusted` channel 没有写工具**。agent 无法追加，只能读。
3. **`untrusted` 内容写入即被引用化**，且每个追加块有固定前缀；
   读取时再叠一层固定横幅。两道都是结构性的，不靠模型遵守。
4. **每个可写 channel 是独立工具名**，守卫按名放行。
5. **没有任意路径参数**。`file` 必须是配置里的相对文件名，启动时校验（拒绝 `..`、绝对路径）。
6. **安装只动自己的块**。`cordis.patch.yml` 里的标记区块之外不改一个字节。

## 故障模式与行为

| 故障 | 行为 |
|---|---|
| 记忆文件不存在 | 读返回"还不存在"，不抛错；首次追加时自动创建 |
| 文件损坏（非 UTF-8 垃圾） | 读会返回内容；追加仍然成功（append 不解析旧内容） |
| 文件过大 | 追加后按行轮转，保留最近约 200 KB |
| 适配器加载失败 | 只跳过该适配器，`digest_list` 里标 ⚠️ 与原因 |
| 适配器 read() 抛错 | 返回错误文本，不影响其它适配器 |
| 配置非法 | 启动即失败并打印原因（不会半启动） |

## 为什么不是数据库

- 记忆是**低频写、低频读**的（一天几十条），文件足够；
- 人能直接打开看、grep、diff、备份——出问题时不需要额外工具；
- 没有 schema 迁移负担。

代价：并发写没有事务保证。本项目用 `appendFileSync` + 单行块写入，
在"多个 agent 偶尔追加"这个量级下足够；需要强一致请换 SQLite。
